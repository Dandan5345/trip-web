# TripEase Web

The public web client for [TripEase](https://apps.apple.com/app/id0000000000) — a
desktop editor for **one** trip at a time.

It is deliberately not a copy of the mobile app. There is no sign-in, no trip
list and no account area. You open the site, it shows a code, you scan or type
that code in the TripEase app on your phone, and the trip you had open there
opens here — on a screen wide enough to actually plan on.

## How pairing works

```
browser                                   phone (TripEase app)
───────                                   ────────────────────
sign in anonymously  ─────────────┐
generate ECDH P-256 key pair      │       user opens a trip → Share
  (private key non-extractable)   │       → "Open the site on your computer"
publish web_sessions/{uid}:       │
  status: pending                 │
  nonceHash  = SHA-256(code)      │
  browserPublicKey                │
  origin, expiresAt (5 min)       │
render QR + 8-character code  ────┼────►  scan the QR, or type the code
                                  │       read the session, check the code
                                  │       against nonceHash
                                  │       show what is about to be granted
                                  │       ↓ user confirms
                                  │       ECDH(browser public key)
                                  │         → HKDF-SHA256
                                  │         → AES-256-GCM wrap of the trip key
                                  │       write status: approved, tripId,
                                  │         canEdit, canViewSensitive,
                                  │         wrappedTripKey, expiresAt (12 h)
onSnapshot sees approved  ◄───────┘
unwrap the trip key in memory
read shared_trips/{tripId} live
```

The QR and the code are the same secret. The code exists because a camera is
not always available.

**What the code never contains:** the trip, the trip's encryption key, any
personal data, a Firebase refresh token, or any grant that outlives it.

## Encryption

TripEase trips are encrypted end to end with a per-trip AES-256 key that lives
in the phone's Keychain / Keystore. The server stores ciphertext.

For this client to show anything useful, that key has to reach the browser
without reaching the server:

1. The browser makes an ECDH P-256 key pair. The private key is
   **non-extractable** and lives only in this tab's memory — not in
   `localStorage`, not in `sessionStorage`, not in IndexedDB.
2. The phone does the key agreement against the published public key, derives a
   wrapping key with **HKDF-SHA256**, and wraps the trip key with
   **AES-256-GCM**.
3. The AAD binds the wrapped key to `webUid | tripId | ownerUid |
   encryptionVersion`, so a blob from one session cannot be opened by another.
4. The browser unwraps it locally and uses it to decrypt the trip's sensitive
   fields — the `TE2` envelope (`AES-CTR` + `HMAC-SHA256`) the app writes.

The plain trip key is never persisted, never logged, never put in a URL, and
never sent to any server. Refreshing the page throws it away, and the session
has to be paired again.

If the phone did not grant access to sensitive data, no key is sent at all, and
those fields stay visibly locked rather than rendering as broken text.

`src/crypto/` holds all of this; `test/crypto-interop.test.ts` pins it against
vectors generated by the Dart implementation, and vice versa.

## Running it

```bash
npm install
npm run dev          # http://localhost:5173
```

The Firebase web configuration is baked in (it is public by design — it
identifies the project, it authorises nothing). Copy `.env.example` to
`.env.local` to point the client somewhere else.

```bash
npm run lint         # eslint
npm run typecheck    # tsc
npm test             # vitest, including the Dart ↔ TypeScript crypto vectors
npm run build        # production bundle into dist/
```

## Deploying

The public site is deployed by GitHub Actions to
**https://dandan5345.github.io/trip-web/**. Every push to `main` runs lint,
type checking and tests, builds with the `/trip-web/` base path, and deploys
the result to GitHub Pages.

```bash
npm run build:pages   # the exact GitHub Pages bundle, including SPA 404 fallback
```

`404.html` is an intentional copy of the app shell. GitHub Pages has no SPA
rewrite setting, so this lets a direct visit or refresh below `/trip-web/trip`
load React Router instead of showing GitHub's 404 page.

The old `firebase.json` remains only as a reproducible fallback configuration;
Firebase Hosting is not the production host for this repository.

## Layout

```
src/

  firebase/   app bootstrap, public config, App Check

  pairing/    the QR screen
  trip/       the trip document model, live hook, home screen, modals

  i18n/       Hebrew and English strings
  ui/         modal, skeletons, badges, notices
test/
  fixtures/   crypto vectors shared with the Flutter repo
```

## Security notes

- No third-party script is loaded. Everything is bundled.
- No secret, service account or private API key is in this repository.
- The session expires on its own (12 hours), locks after 20 minutes of
  inactivity, and can be ended from either the browser or the phone.
- Firestore rules scope an approved session to exactly one `tripId`, refuse
  writes without `canEdit`, and refuse sensitive reads without
  `canViewSensitive`. A session cannot widen its own grant or approve itself.
- Firebase's browser configuration is an identifier, not a private credential.
  Cloudflare Worker and R2 credentials remain encrypted Worker secrets and are
  never copied into this repository or sent to the browser.

## Status

The pairing flow and the trip home screen are complete. The sections a home
card links to — places, hotels & transfers, schedule, confirmations, documents,
expenses, map — currently open a placeholder page that names the section and
links back. They are built in the mobile app.
